# MuCap non-speech transcription

기본 모드는 **녹음 → 전사를 먼저 표시 → 시각화·햅틱 자동 추가**입니다.

- **전사만 먼저 보기 OFF**: 전사·시각화·햅틱을 생성합니다. 전사는 후속 생성을 기다리지 않고 표시됩니다.
- **전사만 먼저 보기 ON**: 전사만 요청합니다. 결과 아래 **시각화·햅틱 추가 생성**으로 나중에 이어갈 수 있습니다.
- 추가 생성은 저장된 전사와 원본 녹음을 사용하며 전사 모델을 다시 호출하지 않습니다. 실패해도 전사를 유지하고 추가 생성만 재시도합니다.
- **통합 재생**으로 오디오·시각화·iPhone 진동을 함께 재생하고 정지합니다.

STT 전송과 STT API 키 asset 로드는 제거한 상태를 유지합니다.

## 실행

MuCap 프로젝트에서 서버를 먼저 실행하세요.

```sh
./script/run_mobile_server.sh
```

이 Flutter 프로젝트에서는:

```sh
./tool/run_mucap_local.sh macos
./tool/run_mucap_local.sh iPhone
```

iPhone 실행은 현재 Mac의 Wi-Fi 주소를 넣은 릴리스 빌드를 사용합니다. 두 기기가 같은 Wi-Fi에 있어야 하며 iPhone의 로컬 네트워크 권한을 허용해야 합니다. Mac 주소가 바뀌면 스크립트로 다시 실행하세요. 여러 iPhone이 있으면 이름 대신 기기 ID를 사용할 수 있습니다.

## 분리된 파이프라인

- `/transcribe`: 오디오 특징 분석과 MuCap 모델 호출 후 `captions[{time,end,text}]` 반환. 시각화·햅틱은 생성하지 않습니다.
- `/outputs`: 원본 WAV(base64)와 기존 전사를 받아 시각화·햅틱만 추가합니다.
- `/analyze`: 기존 전체 파이프라인 유지. 시각화 속성과 햅틱 이벤트까지 생성합니다.
- 앱의 `NonspeechTranscription`은 스타일·햅틱 필드 없이 전사 결과를 처리합니다. 시각화·Core Haptics는 추가 생성 결과에 연결되어 있습니다.

현재 의성어 생성은 기존 MuCap 음악·악기 중심 프롬프트를 그대로 사용합니다. 일반 환경음 전체에 대한 모델 품질 개선은 별도 작업입니다. 전사만 요청하더라도 특징 추출과 모델 응답 대기는 필요합니다.

실제 OpenAI 키는 서버의 `mucap/.env`에서 읽습니다. 앱에는 MuCap 서버 주소만 전달합니다. HTTP 오류는 서버의 사유를 함께 표시하며 API 키는 표시하지 않습니다.

시각화·햅틱 생성 후 **통합 재생**을 누르면 녹음·시각화·내장 진동이 함께 재생됩니다. iOS는 오디오와 Core Haptics를 준비한 뒤 같은 시작 시점으로 예약합니다. **재생 정지**, 다른 기록 재생, 앱 비활성화 시 함께 정지하며 재시작은 처음부터 진행합니다. 전사만 있는 기록은 **녹음 듣기**를 사용하며, 햅틱 미지원 기기는 오디오·시각화만 재생합니다.

## lib 폴더 구조

- `main.dart`: 앱 시작점과 테마
- `pages/`: 화면과 화면 상태 관리
- `widgets/`: 재사용 UI (MuCap 시각화)
- `services/`: API 클라이언트와 네이티브 녹음·햅틱 호출
- `models/`: 전사 데이터와 시각화 스타일 형식
- `config/`: 개발자 설정 로딩
- `utils/`: 공통 API 오류 처리
